에스더님 지시: "지금부터 만들 앱들은 기본 엠비티아이 구조로 설계한다고 저장해."

**규칙**: 앞으로 신규로 만드는 모든 앱(웹앱·토스 미니앱 불문)은 `app/mbti/` (랜딩+퀴즈 `page.tsx`, 결과지 `result/[id]/page.tsx`, API `api/mbti/analyze/route.ts`)를 기본 참조 구조로 삼는다. 공유 버튼 문구뿐 아니라 **전체 설계 방식**(무료 퀴즈 → 결과지 무료 요약 + 유료 심층 잠금박스+카운트다운 → 전화번호 매칭 잠금해제 → MBTI식 공유버튼)을 기본값으로 시작한다.

- [[feedback_share_button_mbti_style_copy_2026_08_27]] — 이 지시보다 먼저 저장된 공유버튼 한정 규칙. 이번 지시로 범위가 "공유버튼만"에서 "앱 전체 구조 기본값"으로 확장됨.
- [[project_sonjeolgak_app_launch_2026_08_27]] — 손절각 앱을 MBTI 구조로 재설계하며 나온 패턴이 이번 결정의 실제 사례.

**Why**: 매번 새 앱 구조를 처음부터 다시 설계하다 보니 손절각처럼 나중에 MBTI와 어긋나는 부분(공유버튼, 카드 레이아웃, 콘텐츠 분량, 잠금조건)이 생겨 재작업이 발생함. 처음부터 MBTI를 기본틀로 잡으면 이런 불일치와 재작업을 예방할 수 있음.

**How to apply**: 새 앱을 처음 설계/코딩할 때 임의로 다른 구조를 먼저 제안하지 말고, MBTI 구조를 기본값으로 깔고 시작한다. 앱 특성상 정말 안 맞는 부분(예: 일기형 앱의 누적 기록 구조)만 예외로 다르게 설계하고, 그 경우엔 왜 다른지 먼저 설명한다.
