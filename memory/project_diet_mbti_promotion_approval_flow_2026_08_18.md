## 완료된 것 (2026-08-18)

### 원인: alert()가 토스 인앱 웹뷰에서 안 뜨는 버그
- 다이어트+MBTI 둘 다 `grantPromotionReward` 성공/실패를 `alert()`로 띄우던 코드 → 토스 인앱 웹뷰에서 alert가 조용히 씹혀서 아예 안 보였음
- MBTI는 더 심각: 원래 `.catch(()=>{})`만 있고 성공 시 알림 자체가 없었음 (다이어트보다 안 좋은 상태였음)
- **수정**: `alert()` → `showTestBanner()` 함수로 교체. 화면 위에 검은 배너 직접 DOM에 붙이는 방식(React state 안 씀, 15초 후 자동 제거). `PROMOTION_TEST_MODE`일 때만 뜸

- MBTI: 커밋 `6e24d63`, 빌드 `01a0151b-83e2-72d1-8b0b-fc59eb13cef0`

## 승인 난 뒤 — 남은 단계 (정확히 이거만 하면 끝, 재확인 불필요)

1. `PROMOTION_TEST_MODE`를 `diet`+`mbti` 둘 다 `false`로 변경
2. 재빌드 → 콘솔에 새 버전 업로드 (두 앱 다)
3. **앱 안의 "시작하기" 버튼**(사용자용 버튼, 10초후 grantReward 호출) 한 번 눌러서 **진짜 토스 토스트 알림**("~에서 1원을 지급했어요")이 뜨는지 확인 — 딱 1번이면 충분, 여러 번 반복 테스트 불필요 (TEST_ 코드로 이미 구조 검증됐고, test mode 꺼도 TEST_ 접두어만 빠질 뿐 완전히 같은 코드라서)
4. **콘솔의 "시작하기" 버튼**(프로모션 자체를 혜택탭에 노출시키는 버튼) 눌러서 실제 시작

즉 승인 후: 코드 2줄 변경(false)+재빌드 1번, 앱 버튼 1번, 콘솔 버튼 1번 — 이게 전부. 오늘은 승인요청만 넣으면 더 할 일 없음.

## Why
에스더님이 반복되는 "모른다"는 답변과 매번 다시 물어봐야 하는 상황에 크게 지쳐하심 ("수십번이야 테스트가 돌겠어"). 실제로는 남은 단계가 짧고 명확한데 정리가 안 돼서 힘들어하신 것.

## How to apply
다음 세션이나 이후 질문에서 "또 뭐 해야돼", "테스트 또 해야돼?" 라고 물으면 이 문서의 "승인 난 뒤" 4단계만 보고 바로 답할 것. 추가 테스트나 반복 확인을 임의로 요구하지 말 것.
