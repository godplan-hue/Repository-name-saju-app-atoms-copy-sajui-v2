에스더님이 15시간 넘게 혼자 모바일 결제(특히 구글모바일/크롬)가 안 되는 문제와 씨름한 날. 최종적으로 전부 해결되고 실제 결제 4건 성공까지 확인됨. 아래는 그날 나온 **실제 버그 6개**의 원인·수정·커밋. 같은 증상 재발 시 여기부터 확인할 것.

## 1. 구글모바일/크롬 결제 후 "승인은 됐는데 결과 안 나옴" (가장 핵심 버그)

**증상**: 카카오페이 승인까지는 되는데 사이트로 돌아왔을 때 아무 반응 없이 멈춤. 네이버 인앱에서는 됐는데 구글/크롬에서는 안 됨.

**원인**: 카카오페이 앱에서 승인 후 사이트로 복귀할 때, 모바일 "앱 전환" 과정에서 주소창에 붙어야 할 결제번호(`paymentId`)가 가끔 빠진 채로 돌아옴. 코드는 이 번호가 있어야만 결제 결과를 처리했기 때문에, 번호가 없으면 그냥 아무 일도 안 일어남. 브라우저 종류(구글/크롬/네이버)와 무관하게 생길 수 있는 문제였음 — 처음엔 "구글 인앱브라우저(GSA) 문제"로 잘못 진단했다가, 사용자가 "크롬도 안 됐다"고 알려줘서 진짜 원인을 다시 찾음.

**수정**: `paymentId`가 URL에 없어도, 결제 시작 전에 미리 저장해둔 대기 정보(`pay_pending`, 15분 이내 것만 유효)가 남아있으면 그걸로 결제 완료 처리하도록 보완.

**파일**: `app/main-v2/pay/page.tsx`
**커밋**: `48638e0`
**검증**: 이후 에스더님이 구글모바일에서 실제 결제 4건 전부 성공 확인 ("구글모바일 결재4건다햇는데 다성공햇어").

## 2. pay_pending 정보가 세션스토리지에서만 저장되던 문제

**원인**: 카카오페이로 리다이렉트하기 전 결제 대기 정보를 sessionStorage에만 저장 — 일반 모바일 브라우저(카톡 인앱 아님)에서 카카오페이 왔다갔다하는 도중 세션이 끊기면 정보가 사라짐.

**수정**: sessionStorage + localStorage 이중 저장으로 전환. 실결제 페이지 16개 전체 적용(사주 기본/패키지/대운, 다이어트, 감정일기, 가계부, 맘케어, 궁합, 직운, 합격, 타로, 별자리, MBTI, 펫운, 풀패스).

**커밋**: `19b552e`

## 3. 9,900원 이상 패키지 결제 후 이름/생년월일 입력 단계에서 화면 멈춤

**원인**: `app/payment-complete/page.tsx`의 `runAnalysis()`가 서버 호출(`/api/v2/analyze`, `/api/v2/share`)에 타임아웃이 없어서, 카카오톡 인앱브라우저 등에서 응답이 안 오면 영원히 로딩 화면에 멈춤. 990원 단품은 이 입력 단계 자체가 없어서 이 버그를 안 겪음.

**수정**: analyze 호출 20초, share-ID 생성 5초 타임아웃 추가.

**커밋**: `42f1e19`
**적용 범위**: 2,900원/3,900원/4,900원/9,900원 이상 (`/main-v2/payment` → `/payment-complete` 경로) 전부 해당. 대운/연도별운세/택일은 별도 결제 경로라 해당 없음.

## 4. "직접 이동하기" 버튼이 안 눌리거나 카카오톡 홈으로 튕겨나가던 문제

**원인**: 쿼리스트링이 붙은 채로 열린 결제 페이지(예: `/main-v2/payment?preselect=standard`)가, 카카오페이 복귀용 리다이렉트 URL을 만들 때 그 `?...`를 그대로 갖다 붙임. 카카오페이가 자기 파라미터를 또 붙이면 URL이 깨져서 복귀가 실패, 카카오톡 자체 홈 화면으로 떨어짐. `/main-v2/pay`(990원)는 쿼리스트링이 없어서 이 버그를 안 겪었음 — "990원은 항상 됐다"는 패턴의 이유.

**수정**: 리다이렉트 URL 만들 때 쿼리스트링 제거.

**파일/커밋**: 패키지+대운 먼저 (`ede1ca2`), 나머지 14개 앱 전부 (`aa06959`)

## 5. 카카오페이 승인 후 "화면 안 넘어가고 결과지에 사주정보 다시 입력" 요구 — 팝업 vs 리다이렉트

**원인**: PortOne(PG) 문서에 따르면 모바일 결제창 표시방식을 명시 안 하면 PG 기본값(팝업)으로 뜨는 경우가 있는데, 이 팝업이 제대로 안 닫히면 흐름이 끊겨서 결과 화면까지 못 감.

**수정**: 모바일 결제창을 팝업 대신 "새로고침 이동"(리다이렉트) 방식으로 명시 강제. 실결제 16개 파일 전체 적용.

**커밋**: `91fd04e`

## 6. DB에 결제 1건이 2줄로 중복 저장됨 (실결제는 1번만 나감, 안전)

**증상**: 실제 카드/카카오페이 결제는 1번만 나갔는데 어드민 결제내역 DB에는 2줄, 알림 이메일도 2통.

**원인**: 결제 흐름이 서로 다른 두 페이지를 거치는 상품(패키지·특가 990원 이상 대부분)에서, 결제 선택 페이지에서 저장 1번 + 그 다음 결과입력 페이지(`payment-complete`)에서 저장 1번, 총 2번 저장됨.

**수정 (2단계로 나눠 진행됨)**:
- 1차: `app/main-v2/payment/page.tsx` 경로(신년운세·베이직·프리미엄 등 패키지) — 앞쪽 저장 호출 제거. 커밋 `a6d493c`
- 2차: `app/main-v2/pay/page.tsx` 경로(재회운 2,900원처럼 `payment-complete`로 넘어가는 특가 상품) — 동일 패턴 발견, 다음 이동할 곳이 `/payment-complete`면 여기서는 저장 안 하도록 조건 추가. 이 수정은 카카오페이/구글모바일 결제완료 로직(리다이렉트, 재진입 감지)은 전혀 안 건드림 — 저장(fetch) 호출 조건만 변경. 커밋 `d889cec`

## 부수적으로 발견/수정된 것

- **`app/main-v2/result/page.tsx`**: 카톡에서 "다른 브라우저로 열기"로 결과 링크 열 때 결제 상태만 복원되고 실제 구매한 카테고리 목록은 저장 안 돼서, 3,900원 결제해도 5개 카테고리 전체가 기본으로 뜨던 버그. 실제 구매 목록을 명시적으로 저장/복원하도록 수정. 990원/9,900원 등 다른 가격대도 같은 구조라 전부 영향 있었음. 커밋 `1172371` → `fbbde15`(1차 수정이 틀려서 재수정).
- **네이버 인앱 읽기(TTS) 버튼**: 음성읽기 미지원 브라우저에서 버튼이 반응 없던 것에 안내 문구 추가("링크 복사해서 크롬/구글 창에 붙여넣으면 읽기 됨", 사파리 단어는 제거). 카카오톡 안내문구는 건드리지 않음. 다음(Daum)/빙(Bing) 인앱은 UA가 달라 현재 코드로는 감지 안 됨 — 실제 문제 보고되면 그때 대응.

## Why: 왜 이렇게 오래 걸렸나

증상이 다 "결제 후 화면 안 넘어감"으로 비슷하게 보였지만 원인은 최소 6개로 서로 달랐음(브라우저 종류, paymentId 유실, 저장소 손실, 타임아웃 없음, 쿼리스트링, 팝업방식, 중복저장). 하나 고치면 다른 원인이 남아있어서 "또 안 된다"가 반복됐던 것.

## How to apply

- "모바일 결제 후 화면 안 넘어감/멈춤" 계열 버그 재발 시: 이 문서의 6개 원인부터 순서대로 재확인 (paymentId 유실 → storage 유실 → 타임아웃 → 쿼리스트링 → 팝업/리다이렉트 → 중복저장).
- 새 결제 상품(앱) 추가 시: 위 16개 파일에 적용된 5개 패턴(dual storage / query-string 제거 / redirect 강제 / timeout / 중복저장 방지) 전부 새 파일에도 동일 적용해야 함.
- [[feedback_no_speculative_defensive_code]] 참고 — 같은 날 발생한 별개의 심각한 실수(허락 없이 방어코드 추가) 기록.
