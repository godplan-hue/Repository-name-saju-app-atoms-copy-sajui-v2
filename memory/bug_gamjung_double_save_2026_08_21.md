**증상**: 감정일기(gamjung)에서 일기 하나 작성해서 제출했는데, 보관함에 똑같은 날짜·기분의 기록이 2개씩 저장됨. 에스더님이 직접 재현: "빙금또하니또2개저장되" (한 번 더 해봤는데 또 2개 저장됨).

**원인**: `app/gamjung/page.tsx`의 "활동 선택" 단계(2/3단계)에 있는 "다음으로 →" 버튼 — 이미 전화번호+개인정보동의가 저장된 재방문자는 이 버튼을 누르면 폼 단계를 건너뛰고 바로 `analyze()`(저장 함수)가 실행됨. 그런데 이 버튼엔 로딩 중 재클릭 방지(`disabled`)가 전혀 없었음 (3단계 폼 화면의 제출 버튼만 `disabled={loading}`으로 막혀있었음). 버튼을 연타하면(모바일에서 흔함) `analyze()`가 두 번 실행되고, 서버에도 두 번 요청이 가서 Firebase에 별개의 기록 2개가 생성됨.

**수정**: `app/gamjung/page.tsx`
- `analyze()` 함수 안에 `submittingRef`(useRef) 동기 재진입 방지 가드 추가 — state(`loading`)는 비동기라 연타를 못 막지만 ref는 즉시 반영되므로 확실히 막음.
- 활동 선택 단계의 "다음으로" 버튼에도 `disabled={loading}` + 로딩 텍스트 표시 추가 (폼 단계 버튼과 동일한 패턴).

**Why**: 감정일기는 `analyze()` 호출 지점이 2군데(활동 단계 자동스킵 버튼 + 폼 단계 제출 버튼)인데, 폼 단계 버튼만 가드가 있고 활동 단계 버튼은 가드가 없었던 게 근본 원인. 다이어트/가계부/맘케어는 전체 배열을 덮어쓰는 저장 구조라 이 문제와 구조가 다름 — 별도 확인 필요.

**How to apply**: 앞으로 gamjung처럼 "제출 버튼이 여러 화면에 나뉘어 있는" 구조를 만들 때는, 모든 제출 버튼에 동일한 로딩 가드를 넣을 것. 이 버그는 [[feedback_diet_app_no_touch]](이제 해제됨)와 무관하게, 실제 재현된 코드 버그였음.
