> 에스더님이 "앞에 똑똑이가 이거 잘못 찾는다"고 직접 지적해서 새로 명확히 정리한 파일.
> 광고구조 관련 질문 오면 이 파일부터 확인할 것. [[project_toss_ad_structure_v2_final]]는 3개앱(MBTI/다이어트/감정일기) 세부 잠금표만 다루고, 이 파일이 17개 앱 전체 공통 구조 + 최신 결정사항.

## 목적 (가장 중요)

**17개 앱은 결제수익이 아니라 광고수익이 주목적.** 처음엔 폼(DB입력)을 앞에 뒀더니 아무도 가입 안 해서, 퀴즈/콘텐츠 먼저 보여주고 마지막에 폼 넣는 구조로 전체 변경함.

## 공통 광고 구조 (모든 앱 동일)

1. **앱 클릭(첫 진입) 시** → 첫 화면에서 전면광고 1회
2. **결과지 나오기 직전** → 전면광고 1회 더
3. **결과 내용(섹션)마다 잠금** → 클릭해서 열 때마다 광고 1회씩 (섹션 개수만큼 광고 노출)

## 일기류 앱 (감정일기·맘케어·가계부 등) 히스토리 포인트 구조

- 하루치 히스토리(과거 기록) 보려면 **2,000포인트** 필요
- 포인트 적립: **출석 체크 + 광고 3회 시청**
- 즉 히스토리 보고 싶으면 자연스럽게 광고 3번 더 보게 되는 구조

## ⭐ MBTI 이중 광고 — 2026-08-13 결정: 그대로 유지

- 원래 설계: 첫 진입 시에만 전면광고 1회
- **실수로 "시작하기" 버튼 클릭 시에도 광고가 한 번 더 나감** → 사실상 진입 직후 광고 2연속
- 에스더님이 원래 이 버그를 고쳐서 재빌드하려 했으나, 실제 데이터 확인 결과 **광고 2번 연달아 나와도 사용자들이 이탈 안 하고 계속 진행**
- 목적이 광고수익이므로 오히려 광고 노출 1회 더 버는 셈 → **고치지 않고 이 상태 그대로 올리기로 결정**
- Claude 의견(2026-08-13): 데이터상 이탈 없으면 그대로 유지가 맞음. 다만 이걸 정식 패턴으로 다른 신규앱에도 일부러 넣을지는 별개 문제 — 넣기 전엔 며칠 더 리텐션 지켜보고 판단할 것 (지금은 "실수인데 해가 없어서 안 고친 것"이지 "검증된 전략"은 아직 아님).

**Why:** 사용자가 이 정리 없이 매번 다시 설명해야 해서 시간 낭비되고 있음 — 명확히 한 곳에 저장해서 다음 세션에서 바로 찾게 하기 위함.
**How to apply:** 광고구조/포인트구조 질문 오면 이 파일 먼저 읽을 것. 새 앱 만들 때도 이 3단계 광고구조(진입/결과직전/섹션마다)를 기본값으로 적용.
