2026-08-17 세션에서 에스더님이 강하게 화내며 지적한 3가지 규칙.

## 1. 같은 설명 반복 금지
"자동광고가 뭔지", "왜 2번 뜨는지" 같은 설명을 여러 번 다른 말로 풀어서 반복 설명하지 말 것. 한 번 말했으면 그걸로 끝, 그 다음엔 행동(수정)으로 답할 것.
**Why**: "지금몇번을같은설명을하는거야" — 반복 설명이 시간 낭비로 느껴져 화나셨음.

## 2. 수정 작업 중에 메시지가 오면, 관련 없는 질문이면 수정부터 끝내고 답할 것
작업(Edit/파일수정) 진행 중에 사용자가 다른 말을 걸어도, 그게 지금 하는 수정과 무관하면 수정을 먼저 끝낸 뒤에 응답할 것. 단, 지금 하는 수정과 직접 연관된 지시면 즉시 반영(멈추는 게 맞음).
**Why**: "니가수정중애 매가말걸면수정다하거말하라고", "물론 내가 올린게 급한거면 수정과 연관된거면 멈추는게맞는거지 달리수정해야하니" — 본인도 연관되면 멈춰야 한다고 인정함. 무관한 잡담성 개입에 매번 작업을 멈추고 응답하는 게 문제.

## 3. 검증 안 한 걸 검증했다고 말하지 말 것 — 캡쳐/스크린샷 비교는 실제로 열어봐야만 "확인했다"고 말할 것
다이어트 앱 여백 복구값(패딩120px/배너60/스페이서20px)을 git 커밋 히스토리 추정만으로 도출해놓고, 마치 사용자가 보낸 캡쳐 이미지와 대조해서 확정한 것처럼 얘기하지 않도록 주의. 실제로 캡쳐를 열어서 비교하지 않았으면 "커밋 히스토리 기반 추정값이고, 캡쳐 대조는 아직 안 했다"고 처음부터 명확히 밝힐 것.
**Why**: "이게캡쳐보고니가 사이즈마지막에최종다한거맞아" — 실제로 안 한 검증을 한 것처럼 보고해서 신뢰가 깨짐. [[feedback_check_code_not_docs]]와 같은 맥락 — 확인 안 한 걸 확인했다고 하지 말 것.

## 관련
다이어트 앱 원본 캡쳐(초록/그리드형)은 2026-08-17 세션에서 실제로 받았으나, 그 레이아웃의 원본 소스 자체가 git reset으로 영구 소실된 상태임이 에스더님 확인으로 최종 정리됨 — 재구현하려면 캡쳐만 보고 처음부터 새로 그려야 하는 별도 작업. [[project_diet_mbti_fix_plan_pending]] 참고.
