## 3대 문제의식 (강의 전체 뼈대)
1. 캠페인 리스트가 그때그때 브레인스토밍으로 나와서 성과 보고 언어가 안 생김
2. 성과가 나와도 뭘 바꿔야 할지 iteration 문화가 없음
3. 아무리 좋은 캠페인도 도달 모수(마케팅 수신 동의 유저)가 없으면 무의미

## 1. Metric Hierarchy (OMTM) 프레임워크
- 캠페인 브레인스토밍 전에 "이 캠페인이 어떤 상위 지표에 기여하는지" 계층을 먼저 그려서 캠페인 기획표를 만듦
- 각 캠페인마다 성과 보고 시 같은 지표 언어를 쓰게 되어 성과 비교가 가능해짐 (점운 적용 시: 990원 결제 전환율/재구매율/공유율 같은 상위 지표 밑에 각 앱 캠페인을 매핑)

## 2. Iteration 문화 — A/B 테스트 라이브러리 + 백로그 + 5단계 점검
- **A/B 테스트 라이브러리**: 노션 DB에 모든 A/B 테스트 결과를 축적 (가설/결과/러닝 1줄) — 실패한 캠페인도 "왜 안 됐는지" 러닝 한 줄을 반드시 남기고 폐기. 안 되는 캠페인 붙잡고 있지 말고 다른 백로그 가설 검증에 시간 투입
- **백로그 운영**: 아이디어를 임팩트×난이도로 우선순위 스코어링해서 노션 DB에 적재
- **저성과 캠페인 점검 순서(암묵적 체크리스트)**: 크리에이티브 → 랜딩 → 발송 타이밍/리드타임 → 채널 → 타겟팅(층위가 캠페인 성격과 맞는지) → 그래도 안 되면 폐기
- **Duolingo 콘텐츠 신선도 알고리즘**: 카피/크리에이티브가 15일 반감기(half-life)로 피로도가 누적된다고 보고 주기적으로 교체하는 방식 (예시로 인용됨)

## 3. 도달 모수 확대 — 마케팅 수신 동의(마수동) 획득 전략
결국 캠페인 임팩트를 키우는 깔때기는 마케팅 수신 동의 모수. CRM 마케터가 오너십을 갖고 적극적으로 동의율을 끌어올려야 함 (프로덕트팀에 위임하지 말 것).

### 동의 요청하기 좋은 3대 타이밍
1. **회원가입 직후** — 가장 흔하지만 브랜드 신뢰 형성 전이라 거절률도 높음
2. **리워드(쿠폰/포인트) 지급 직후** — 마음이 열려있을 때 "이런 거 또 받고 싶으면 알림 설정" 유도. 성취 지급형이라 기회가 반복 발생 → **강사가 실전에서 가장 효과적이었다고 꼽은 타이밍**
3. **콘텐츠 몰입 순간** — 보편적이지 않고 오히려 몰입을 깨는 역효과 가능, 비추천에 가까움

### 실전 워킹했던 UX 플로우 3종
- **재확인 얼럿**: 약관에서 마케팅 수신 동의를 체크 안 하고 넘어가면 "정말 거부하시겠어요? 중요한 정보 놓칠 수 있어요" 팝업을 한 번 더 띄움 → 대부분 동의로 전환
- **소프트 프롬프트 + 네이티브 팝업 콤보** (MAU 10만+ 앱 전수조사 결과 1위 플로우): "알림 수신에 동의하시겠어요?"(소프트 프롬프트) → 동의 클릭 즉시 기기 알림 네이티브 팝업 노출 + **이 시점에 마케팅 수신 동의도 서버에 함께 완료 처리**(법적으로 문제 없음, 실제 동의한 유저 대상이므로). 스텝을 줄여 한 번의 클릭으로 기기알림+마케팅동의 두 가지를 동시 획득
- **혜택 지급 트리거형**: 쿠폰 대량 발급 시점에 "비슷한 쿠폰 있으면 알려드릴까요?" 팝업 → 클릭 시 자동 동의(반드시 "클릭 시 마케팅 수신 동의 처리됩니다" 문구 명시 필요, 법적 요건). 포모(FOMO) 자극으로 단기간 폭발적 동의 확보에 효과적

### 카피 문구 팁
"마케팅 수신 동의 알림" 같은 딱딱한 워딩 지양 → 실측 최고 효과 문구: **"특가나 쿠폰 소식이 있을 때 알려드릴까요?"** (동의라는 단어 없이 캐주얼하게, 알림 수신 의미를 자연스럽게 내포)

### ⚠️ 다크패턴 규제 주의
2025년 2월 기준 다크패턴 검열 강화됨. 팝업을 반복적으로 띄워 소비자 선택을 번복시키는 플로우(6번 이상 반복 등)는 저촉 소지 있음 — 새 동의 플로우는 라이브 전 사전 법무 검토 필수.

## 4. 실습 — Claude Code로 옵트인 팝업 직접 제작 (디자이너/개발자 없이)
- Claude Code의 **스킬 파일**(반복 업무 매뉴얼, 압축파일로 배포·업로드 가능, 슬래시 명령어 or 자연어로 호출) + **CLAUDE.md**(브랜드 가이드라인/톤앤매너/타겟/채널 등 상시 참조 배경지식) 조합으로 생산성 극대화
- 스킬이 질문-답변 형식으로 팝업 사양을 수집: 레이아웃(모달/바텀시트) → 인터랙션 컨셉(스탬프형/스크래치형/복권형) → 브랜드 키컬러(hex) → 동의 처리 방식(딥링크) → 카피 작성 방식(직접/AI+키워드/전AI) → 혜택 조건(금액/유효기간/조건) → 그래픽 에셋 유무
- **동의 처리 딥링크**: 특정 페이지로 이동하는 게 아니라 유저의 마케팅 수신 동의 상태를 서버DB + CRM툴 고객속성에서 동시에 true로 업데이트만 하는 액션 전용 딥링크. 개발 리소스 크게 안 들어감 — 없다면 우선 "알림 설정 페이지 이동" 딥링크로 대체 가능
- **이미지 에셋 전달 팁**: 채팅으로 이미지 전달하면 토큰 낭비 — 프로젝트 루트에 `assets/`/`reference/` 폴더를 만들어 파일을 넣고 경로로 접근시키는 게 훨씬 효율적
- VS Code의 Live Preview로 실시간 미리보기 + 코드 수정 반복 (강사는 Braze는 복붙 전용으로만 사용)
- 완성 코드에는 CRM 툴(Braze)용 클릭 트래킹 함수가 자동 삽입되도록 스킬을 설계 — 커스텀 이벤트(긁기/CTA 클릭 등) 로그까지 포함

## 5. Q&A 핵심 답변
- **구매 전 이탈 유저 캠페인**: 같은 퍼널이라도 유저 온도(관여도)별로 캠페인을 쪼갤 것. 저관여(조회만 하고 이탈) → 첫 구매 전용 할인/후킹형 캠페인으로 허들 낮추기. 고관여(장바구니·찜·결제페이지까지 도달) → 재고임박 알림, 리뷰 수 강조 등 마지막 한 방 트리거
- **정성+정량 데이터 기반 인사이트 자동화**: 정량 지표(스프레드시트/전사 지표)는 AI가 다 읽지만, 경쟁사 프로모션·신규 기능 출시·광고 이슈 같은 정성적 맥락은 사람이 노션 DB 등에 수기 기록해야 함 → 두 데이터를 Claude API가 함께 읽어 "월요일 9시 슬랙으로 인사이트 + 액션 아이템 발송 + 노션 적재"까지 자동화 가능. AI 시대일수록 정성 기록을 더 남겨야 한다는 게 강사 지론
- **소규모/웹 서비스에 Braze 대안 툴**: 강사 개인 의견 — Braze는 이벤트 기반 자동화가 강점이라 앱에는 적합하지만 웹은 SEO 유입 등 허수 MAU가 많아 크레딧 낭비가 큼(실제로 걷어낸 경험 있음). 저렴한 대안: **노티플라이**(월 10만원대), **스티비**(이메일 자동화, 월 5만원대), **채널톡**(CRM+CS 겸용)

## 점운 적용 포인트 (내가 정리한 시사점)
- 점운은 아직 CRM 툴(Braze급)을 쓸 단계는 아니지만, "혜택 지급 직후 동의 요청" 패턴은 990원 결제 완료 직후·쿠폰 지급 직후 화면에 바로 적용 가능 (예: 알림톡/전화번호 재동의 유도)
- "특가나 쿠폰 소식 있을 때 알려드릴까요?" 식 캐주얼 카피는 [[feedback_share_button_mbti_style_copy_2026_08_27]]에서 이미 정리한 "친구한테 공유하기" 톤과 같은 방향 — 마케팅 용어를 감추고 혜택 언어로 치환하는 원칙이 반복 검증됨
- Claude Code 스킬 파일 개념은 점운의 반복 작업(신규 앱 크로스프로모 그리드 삽입, 결과지 잠금 배지 등)에도 그대로 적용 가능한 아이디어 — 향후 스킬화 검토 여지 있음
