# 토스 웨비나 — 박효주 미니앱 성장 비법 (2026-08-20 저장)

에스더님이 앱인토스 8월 웨비나(박효주, "인스타 언팔한 사람 찾기" 개발자, 하루 최대 150만원+ 매출, 8~9개 앱 운영) 전체 스크립트를 저장 요청. "중요한 거 많이 놓쳤다"며 우리 앱 재점검 재료로 사용 예정.

## 1. 로그(Analytics)가 핵심 — 우리 19개 앱 전부 미설치 상태

- 효주님은 개발 단계부터 로그(클릭/노출/화면 체류)를 심어두고, 그 데이터로 이탈 구간(퍼널)을 찾아 개선함.
- 실제 사례: 결과 화면까지 도달한 유저의 **23%가 결제 전환**됨을 로그로 확인 → "이탈을 막으면 결제가 늘겠다"는 가설을 세움.
- 퍼널 4→5단계(인스타그램 앱에서 데이터 요청 후 10~15분 대기하는 구간)에서 이탈이 가장 컸음 → 원인: 유저가 기다리는 동안 앱을 잊어버림.
- **해결책**: 15분 뒤 "결과 나왔어요" 기능성 푸시(스마트 발송) 도입 → 이탈 지점 전환율 **9%→14%로 5%p 개선** (푸시 자체 클릭률 40%, 3만 발송에 만 명 이상 복귀).
- 로그 없이는 이런 개선 자체가 불가능 — "로그는 정의하기 나름"이라 버튼클릭/화면노출/체류시간 등 다 남길 것.
- **에빈토스 프레임워크 자체 Analytics 사용** — 별도 프레임워크 안 만들어도 됨 (screen log, click log 등). 우리도 이미 [[reference_toss_ai_miniapp_build_guide]]에 문법 저장돼 있음 — **아직 코드에 적용은 0/19개** (별도 grep으로 확인된 사실, 이 세션에서 재확인).
- **How to apply**: 다음 앱 업데이트 때 최소한 결과화면 도달/결제 클릭/이탈 지점 후보(로딩 대기 화면 등)에 Analytics.click/screen부터 심는 것을 최우선 순위로 검토.

## 2. 스마트 발송 (Smart Send) — 무료, 토스가 제공

- **광고성 메시지**: 앱을 열어본 적 없는 유저에게도 도달 가능 (혜택 탭 노출 등 경유), 클릭률은 기능성보다 낮음.
- **기능성 메시지**: 유저 행동 기반(동의 필요) 트리거 발송 — 클릭률 훨씬 높음, 위 사례처럼 40%, 다른 사례는 60%까지도 나옴.
- 둘 다 **비용 없음** (토스 제공 기능).
- **세그먼트 활용이 핵심**: 스마트 발송 CTR을 높이려면 전체 발송보다 토스가 제공하는 유저 행동 기반 세그먼트로 좁혀서 보낼 것 (예: 로또 앱이면 40~50대 행동 패턴 세그먼트) — 세그먼트 잘 쓰면 CTR 5%+ 나오는 앱도 있다고 함.
- **프로모션(비즈월렛)**: 유저에게 토스 포인트를 주고 앱을 혜택 탭에 노출시키는 방식 — [[reference_toss_promotion_official_doc]] 에 이미 상세 저장됨, MBTI가 현재 진행중.
- **공유 리워드**: 연락처 공유 시 보상 제공(예: 광고 안 보게 해주기) — 유저가 지인에게 공유하면 메이커는 공유 여부를 추적 가능.
- **공유 링크 이미지 커스텀**: 카톡 등으로 공유될 때 뜨는 미리보기 이미지를 커스텀해서 앱 가치를 직관적으로 전달 가능 (콘솔에서 설정).

## 3. 리뷰 늘리기 — Request Review 타이밍

- `Request Review` API를 호출하면 유저가 현재 화면에서 이탈 없이 바로 별점을 남길 수 있음 (새 화면 이동 불필요).
- **타이밍이 핵심**: 유저가 "기분 좋은 경험"을 한 직후에 띄워야 함 (좋은 결과를 봤을 때 등) — 아무 때나 띄우면 안 좋은 리뷰만 쌓임.
- 효주님 앱: 리뷰 약 7,000개, 평점 4.5+ — 처음엔 100개도 안 되고 평점도 낮았으나 이 방식으로 개선.

## 4. 광고 타입: 전면형 vs 리워드형 — eCPM 차이 큼

- 효주님 앱 실측(참고용, 절대값 아님 — 기간/지면/기능에 따라 유동적): **전면형 ECPM ~2,000원대, 리워드 ECPM ~3만원** — 약 10배 이상 차이.
- 전면형: 5초면 스킵 가능, 유저 부담 적음, 진입장벽 낮음.
- 리워드: 30초 이상 시청 필요 — 보상이 유저에게 "납득 가는" 수준이어야 끝까지 봄. 효주님은 초기엔 전면형만 쓰다가(인앱결제 있어 UX 해칠까 우려) 여러 실험 후 리워드로 정착 — 유저가 로그/대시보드 기준으로 끝까지 시청한다는 게 확인된 뒤 전환.
- **결론(효주님 의견)**: "광고냐 결제냐" 정답은 없음 — 결제할 만한 명확한 가치를 주는 앱은 결제가, 반복 접속 유도형 앱은 광고가 유리. **우리가 논의 중인 "직운/합격 등 유료잠금 앱의 전면형→리워드형 전환" 계획과 정확히 일치하는 패턴** — 유료 앱이라도 광고 자체는 리워드로 바꿔 수익을 올리는 것이 이 강의에서도 검증된 접근.

## 5. 가격(990원) 결정 과정

- 처음엔 2,000원으로 책정 → 팀원 피드백 "절대 안 하겠다" → 3자리수 990원으로 재조정 → 시장 반응 좋음.
- "논리적이라기보다 해보면서 맞춰간 것" — 완벽한 사전 분석보다 실제 유저 피드백 기반 조정을 강조.
- 결제 UX 팁: 일부만 공개하고 나머지는 결제 유도(예: 결과 100명 중 일부만 무료 공개), 단일결제 외 정기구독/할인 등 선택지를 다양하게 제공해 심리적 허들을 낮춤.

## 6. PRD + MCP 토큰 절약 + 스킬(버전관리)

- **PRD 워크플로**: 구글에서 "PRD 스킬" 템플릿 다운로드 → AI에게 제공 → 마이크로 5분 정도 두서없이 말하면 AI가 구조화된 PRD로 정리 + 후속 질문 던짐. 프로젝트별로 유지되는 문서로 관리 — 매번 새로 브리핑할 필요 없음. AI가 개발 범위를 벗어나지 않게 "PRD로 잠가버리는" 역할도 함.
- **MCP 토큰 절약**: 앱인토스 공식 MCP는 호출당 토큰을 많이 씀 → 효주님은 루트에 "에빈토스" 폴더 + "플랫폼 폴더"를 만들어 앱인토스 플랫폼 지식을 문서로 정리해두고, AI가 MCP 대신 이 문서를 직접 읽게 함 — 여러 앱 프로젝트에 걸쳐 토큰 절약.
- **버전 관리 스킬**: 빌드/출시할 때마다 AI에게 버전(1.0.0, 1.0.1 등)과 변경 이력(예: "인앱결제가 정기구독으로 변경")을 GitHub에 자동 기록하게 하는 개인 스킬을 만들어 사용 — 롤백 시 도움됨.
- **Claude + Figma(TDS)**: 앱인토스 개발자센터 "디자인 도구" 페이지에서 TDS(Toss Design System) `.fig` 파일 다운로드 가능 → Claude에 업로드해 20~30분 학습시키면 이후 생성 화면이 자동으로 토스 네이티브 스타일을 따름. (에스더님이 별도로 언급한 "피그마 등 앱인 디자인도 그대로 다운로드해서 넣어두면 크기도 우리가 만들 필요없이 그대로 불러와서 만들 수 있다"는 부분이 바로 이것)

## 7. 인앱결제 두려움 — MCP가 케이스 다 알고 있음

- 결제 대기중/누락/성공 등 케이스를 앱인토스가 이미 세분화해서 문서화해둠 — 개발자가 처음부터 다 구현할 필요 없이 MCP가 알고 있는 도메인 지식을 활용하면 됨. "모든 건 MCP로 귀결된다."

## 8. 문의 응대 자동화 (참고용, 우리와 무관할 수 있음)

- 안 쓰는 컴퓨터에 무료 로컬 LLM을 상시 구동, 1분마다 문의함을 폴링 → 자주 나오는 질문 패턴(환불, 개인정보 등)에 대해 미리 준비한 템플릿 기반으로 AI가 답변 초안을 웹훅으로 디스코드에 전송 → 본인이 보낼지만 결정. 클라우드 API 안 씀(로컬 무료 LLM).

## 9. 마인드셋 / 기타 Q&A 요지

- "완벽하게 갖춰서 출시" 하려다 늦어지는 게 가장 큰 리스크 — 빠르게 출시하고 반응 보고 개선하는 게 낫다는 게 반복 강조된 핵심 메시지.
- 순위(랭킹)는 이미 자리잡은 앱만의 것이 아님 — 신규 앱도 초반 유저 3~4명만 들어와도 상위권 진입 가능. 유지가 관건(retention 관리).
- 성장 전환점으로 가장 크게 꼽은 것: 스마트 발송(기능성 푸시)의 retention 효과.
- 비개발자도 가능 — "에빈토스 MCP" 구글 검색 + 개발자센터의 "AI로 미니앱 개발하기" 가이드로 충분.
- 외부 채널(인스타/스레드/틱톡/에브리타임 등)도 병행 — 타겟 유저가 모이는 곳에 홍보(예: 10대20대 앱이면 에브리타임). 우연히 바이럴된 게시물(조회수 360만)로 하루 검색 유입 2만 명 경험도 있었음 — 예측 불가하니 여러 채널에 가볍게 다 뿌려두는 게 유효.

## Why
에스더님이 "중요한 거 많이 놓쳤다"며 웨비나 스크립트를 저장 요청. 우리 19개 토스 앱에 로그(Analytics)가 0개 설치돼 있다는 사실이 이 강의 핵심 메시지(로그 없이는 개선 불가)와 직접 충돌하는 갭으로 확인됨.

**How to apply**:
1. 다음 앱 업데이트 우선순위 후보: 결과화면 도달률/결제전환/이탈지점에 Analytics 로그부터 심기.
2. 직운/합격 등 유료앱의 전면형→리워드형 광고 전환 계획([[project_mbti_banner_batch_final_and_promotion_launch_2026_08_19]] 관련 논의)은 이 강의에서도 검증된 접근 — 안심하고 진행 가능한 근거로 사용 가능.
3. 스마트 발송(기능성 메시지) 활용도를 앱별로 재점검 — 세그먼트를 좁혀서 CTR을 올리는 방식 고려.
4. 다음 새 앱부터는 PRD 스킬 + 플랫폼 폴더(MCP 토큰 절약) + Figma TDS 워크플로 도입 검토.
