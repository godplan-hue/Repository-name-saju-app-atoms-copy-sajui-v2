에스더님이 2026-08-17 앱인토스 공식 문서 "프로모션" 페이지 전체를 직접 붙여넣어 저장 요청함. [[project_biz_wallet_strategy]]의 실전 진행 상황과 함께 볼 것.

## ⭐ 가장 중요 — "시작하기"를 누르기 전 필수 조건

> **검토가 끝난 뒤 포인트 지급 API 테스트를 최소 1번 완료해야, 프로모션을 시작할 수 있어요.**

즉 콘솔의 "테스트" 버튼은 단순 확인용이 아니라 **"시작하기" 버튼이 활성화되기 위한 필수 관문**이다. 순서:
1. 검토(승인) 완료 → 상태 "진행 전"
2. "테스트하기" 진행 — 앱 코드에서 `TEST_{promotionCode}`로 `grantReward` API를 실제로 최소 1번 성공 호출해야 함
3. 호출 응답의 `resultType`이 `SUCCESS`인지 확인
4. 이 테스트가 성공해야 "시작하기" 버튼으로 실제 프로모션을 시작할 수 있음 (테스트 안 하면 시작 자체가 막혀있을 가능성 높음)

→ 다이어트 앱(`jeomun-diet/src/App.tsx`)은 현재 `PROMOTION_CODE = "01M07WJZ03AHV6S08KCEC26V9W"`, `PROMOTION_TEST_MODE = true`로 코드가 들어가 있음 — 이제 **앱을 실제로 빌드해서 폰에 설치하고, "시작하기" 버튼을 눌러 10초 대기 후 TEST_ 코드 호출이 성공하는지** 확인하는 절차가 남아있음. 이게 되어야 실제 프로모션 "시작하기"가 가능해짐.

## 포인트 지급 시 사용자에게 보이는 것 (테스트 성공 여부 확인 방법)

- **토스트 알림**: 화면 위쪽에 `{{미니앱 이름}}에서 {{금액}}원을 지급했어요` 형식으로 잠깐 떴다가 사라짐 — 실기기에서 눈으로 바로 확인 가능한 가장 쉬운 성공 신호
- **알림 메뉴**(토스 홈 종 버튼)에도 기록 남음 — 단, 사용자 알림 설정에 따라 안 보일 수 있음
- **혜택 탭 → 토스 포인트 → 금액 → 미니앱 이름** 경로로도 적립 내역 확인 가능
- (테스트 모드 중엔 실제 포인트 차감/지급이 안 되므로 위 토스트가 실제로 뜨는지는 별개 확인 필요 — 뜨지 않더라도 콘솔 지급내역/API 응답의 resultType으로 확인하는 게 확실함)

## 필수 안전장치 (검토 시 요구됨)

- 1인 1회 제한, 일일 제한, 쿨다운, 중복 지급 방지 로직 필수
- **1인 하루 최대 지급 금액**: 설정 필수 항목 (다이어트는 1원으로 설정해둠)
- 지급 지연 시 PENDING 상태 안내 + 결과 확인 경로 제공 권장
- 랜덤 지급 불가 — 고정 지급만 허용 (다이어트는 고정 금액 1원이라 OK)
- 사행성 콘텐츠, 자사 앱 설치 유도, 법령 위반 콘텐츠는 프로모션 진행 불가

## 지급 방식 2가지

- **클라이언트 지급** (지금 우리가 쓰는 방식): 앱 코드에서 `Promotion.grantReward()` SDK 함수 직접 호출
- **서버 지급 (Server-to-Server)**: 무결성이 중요할 때(위변조 방지) 사용, **토스 로그인 구현 필수** — 지금 우리 앱들은 이 방식 안 씀

## 성과 대시보드 퍼널 (프로모션 시작 후 확인 가능)

혜택 탭 진입 → 프로모션 클릭 → 포인트 획득, 3단계 퍼널로 이탈 지점 파악 가능. 신규/기존 사용자 구분, 기여매출(워크스페이스 단위만, 미니앱별 불가) 확인 가능. **혜택 탭 미노출로 등록한 프로모션은 대시보드 자체가 안 뜸.**

## 기타 확정 사실

- 프로모션 시작 전 사전 검수 영업일 2~3일 소요 (다이어트는 이미 이 단계 통과함 — 승인 완료 상태)
- 비즈 월렛 충전 최소 50,000원 ~ 최대 30,000,000원 (2026-08-12 인하 반영된 최신 수치, [[project_appintoss_update_2026_08]]과 일치)
- 혜택 탭 미노출로 등록 후 나중에 노출로 바꾸는 것 불가 — 새 프로모션 재등록해야 함
- 프로모션 종료 시 남은 예산은 비즈 월렛으로 자동 환급
