방식 전환 (어려운 앱 → 쉬운 앱)

다이어트 → 칼로리계산기 방식
생년월일 입력 → 오행 체질 분석 → 체질별 권장 칼로리 + 음식 추천
식품DB 필요 없음. 템플릿으로 충분. 🟢 쉬움
예시:
목오행 = 채식 체질, 하루 1,600kcal 권장
화오행 = 고단백 체질, 하루 1,800kcal 권장
재물운·건강운이랑 자연스럽게 연결

가계부 → 일기식 수동입력
날짜 + 금액 + 메모 직접 입력 → Firebase 저장 → 월별 합계 보기
은행 API 없음. 🟢 쉬움
재물운이랑 연결하면 차별화됨:
"이번 달 지출이 많네요 → 재물운 확인해보세요"

식품 칼로리 DB 계획

방법 A — 자체 DB (채택)
자주 먹는 한국 음식 500~1,000개를 JSON 파일로 미리 저장
"콜라" 치면 → 검색 → 칼로리 245kcal 표시
외부 API 없음, 빠름, 무료. 🟢 쉬움

방법 B — 외부 API
식약처 공공 API 연동 → 수십만 개 DB
무료지만 연동 작업 필요. 🟡 중간

→ A 방식 채택: 500개면 일상에서 먹는 음식 90% 커버

음식 1000~3000개 계획 (확정)
카테고리 / 수량
한식 (밥·찌개·국·반찬) / ~600개
패스트푸드·배달 / ~400개
편의점·간식·과자 / ~400개
음료·커피·주류 / ~300개
빵·베이커리·케이크 / ~300개
과일·채소 / ~300개
육류·해산물·달걀 / ~400개
분식·길거리음식 / ~300개
총 ~3,000개 — JSON 파일 약 200~300KB, 완전 가능

사용 방식:
"콜라" 검색 → 콜라 355ml 150kcal 즉시 표시
"삼겹살" 검색 → 삼겹살 100g 331kcal
오늘 먹은 음식 더하기 → 총 칼로리 합산
오행 체질별 "이런 음식 줄이세요" 연결
외부 API 없이 전부 가능
