### 핵심 방식 전환 (어려운 앱 쉽게 만드는 법)

**다이어트**: 식품DB 필요 없음
- 생년월일 → 오행 체질 분석 → 체질별 권장 칼로리
- 목=채식 체질 1,600kcal, 화=고단백 1,800kcal 등
- 식품 칼로리 검색: 3,000개 JSON 직접 저장 (~200~300KB)
  - 카테고리: 한식 600 / 배달 400 / 편의점 400 / 음료 300 / 빵 300 / 과일채소 300 / 육류해산물 400 / 분식 300
  - "콜라" 검색 → 150kcal 즉시 표시
  - 오행 체질별 "이런 음식 줄이세요" 연결
  - 외부 API 없음, 완전 무료

**가계부**: 은행 API 없음
- 날짜 + 금액 + 메모 직접 입력 → Firebase 저장 → 월별 합계
- "이번 달 지출 많네요 → 재물운 확인해보세요" 연결

**AI상담**: 실시간 AI 없음
- 고민 입력 → 키워드 매칭 → 템플릿 답변
- API 비용 0원

### 풀패스 가격 (나중에 — 앱 완성 후 구현)

| 이름 | 가격 | 포함 |
|---|---|---|
| 점운 30일 앱패스 | ₩4,900 | 10개 앱 30일 전체 |
| 점운 30일 풀패스 | ₩6,900 | A안 + 사주 개별운세(재물/연애/건강/성공) |

- **"구독" 단어 절대 금지** → "풀패스", "30일권", "전체이용권" 사용 (카드사 심사 문제)
- 일회성 결제 (자동갱신 없음)
- localStorage `jeomun_pass_until` 하나로 전체 앱 제어
- 구현 시기: 포트원 KCP 실연동 완료 후

**Why:** 사용자가 이 전략을 직접 분석해 정리한 내용. 앱 로드맵과 가격 구조의 근거.

**How to apply:** 새 앱 제안 시 이 순서와 방식 참고. 풀패스는 앱 완성 전까지 절대 구현하지 말 것.
