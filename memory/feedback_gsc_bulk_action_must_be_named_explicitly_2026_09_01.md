에스더님이 화면 캡처를 보내며 스크린샷 기반으로 외부 대시보드(GSC/Vercel/Cloudflare)를 조작하는 세션에서, "사이트맵 재제출이 6,900개 URL 전체를 재크롤링 요청하는 효과가 있다"는 걸 명확히 짚어주지 않아 본인이 직접 1시간 헤매다 버튼을 찾아 눌렀음. "내가1시간정도찾다가버튼찾아서보낸거야" — 명확한 항의.

**Why:** [[bug_dns_cname_fix_google_indexing_2026_08_28]] 케이스에서, URL Inspection의 "다시 요청"(1개씩만 재크롤링)과 Sitemaps 페이지의 "제출"(전체 URL 일괄 재크롤링)은 효과가 완전히 다른데, 이 차이와 "이 버튼을 누르면 6900개 전체가 재신청됩니다"라는 설명을 먼저 안 하고 "재제출은 선택사항, 하고싶으면 하세요" 식으로 애매하게 답변함 — 사용자가 대량처리의 존재 자체를 몰랐던 상황이라 애매한 답이 도움이 안 됨.

**How to apply:** 화면 캡처 기반으로 외부 대시보드를 조작 안내할 때:
1. "이 버튼을 누르면 정확히 무슨 일이 일어나는지"(범위: 1개 vs 전체)를 항상 먼저 설명할 것
2. 대량/일괄처리 옵션이 존재하면 "이게 제일 빠른 방법이에요"라고 먼저 제시할 것 — 사용자가 먼저 찾아내게 두지 말 것
3. "선택사항이에요" 같은 소극적 답변 대신, 상황에 맞는 최선의 액션을 명확히 추천할 것
