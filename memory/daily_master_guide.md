## 💳 토스 인앱결제 — 결제 에러 수정 역사

### ❌ 실패한 방법들
- `TossPay` 임포트 → 404 에러
- `checkoutPayment({ params: { payToken } })` 방식 → "Failed to fetch" (서버 문제)
- `window.location.href` 방식 → 동작 안 함

### ✅ 현재 작동하는 방법 (IAP 직접 방식)
```typescript
import { IAP } from "@apps-in-toss/web-framework";

const payAndUnlock = () => {
  let cleanupFn: (() => void) | null = null;
  cleanupFn = IAP.createOneTimePurchaseOrder({
    options: {
      sku: "ait.0000056127.1b220095.a616820d6a.4818467802",  // MBTI 990원 SKU
      processProductGrant: async () => {
        localStorage.setItem('mbti_paid_v2', 'true');
        setPaid(true);
        setPaying(false);
        cleanupFn?.();
        return true;  // 반드시 true 반환
      },
    },
    onEvent: () => {},
    onError: (error: unknown) => {
      setPaying(false);
      const code = (error as { code?: string })?.code;
      if (code !== "USER_CANCELED") {
        alert("결제 오류: " + (code || "다시 시도해주세요"));
      }
      cleanupFn?.();
    },
  });
};
```

**핵심**: `IAP.createOneTimePurchaseOrder` 사용, SKU는 토스 콘솔에서 생성한 것 사용
**주의**: `processProductGrant`는 반드시 `return true` 해야 함

### 새 앱 SKU 생성 방법
1. 토스 앱인토스 콘솔 → 미니앱 선택 → 인앱결제 → 상품 추가
2. 상품 유형: 소모품 (매번 구매 가능)
3. 가격: 990원
4. SKU 복사 → App.tsx에 붙여넣기

## 📤 공유 잠금해제 — 2단계 방식 (android navigator.share 버그 우회)

**문제**: Android/Toss WebView에서 `navigator.share()` 프로미스가 공유창 열릴 때 즉시 resolve → 실제 공유 안 해도 잠금 해제됨

**해결**: 2단계 UX
```
1단계: "📤 친구에게 공유하고 무료로 보기" 버튼 → 공유창 열기 + shareInitiated=true
2단계: "✅ 공유 완료! 무료로 보기" 초록 버튼 → 이 버튼 눌러야만 실제 잠금 해제
```

## 📺 토스 인앱 광고 — 신청 방법 + 수익화

### 3중 잠금 해제 구조 (MBTI 기준)
```
① 📤 공유하고 무료로 보기 (바이럴)
② 📺 광고 보고 무료로 보기 (리워드 광고 → 높은 eCPM)  ← 광고 ID 오면 추가 예정
③ 💳 990원으로 바로 보기 (결제)
```

### 광고 신청 순서
1. 앱인토스 콘솔 → 미니앱 → 인앱 광고
2. 사업자 정보 등록
3. 정산 정보 입력 (케이뱅크 기획의신 계좌)
4. 광고 그룹 생성 3개: 리워드 / 배너 / 전면형
5. 검토 2-3 영업일 대기
6. **광고 그룹 ID 받으면** → SDK 코드 추가 → 재빌드 → 재업로드

### 수익 공식
`노출수 × eCPM ÷ 1,000 = 수익`
예) 10만번 × ₩5,000 ÷ 1,000 = **₩500,000**

**광고 유형별 eCPM**: 리워드 > 전면형 > 배너

### 리워드 광고 SDK 코드 (광고 ID 받으면 추가)
```typescript
import { TossAds, GoogleAdMob } from "@apps-in-toss/web-framework";
// 광고 ID 받은 후 코드 추가 예정
```

## 🚀 스마트 발송 비법 (로빈 웨비나 2026-07-24 — 핵심만)

> 상세 내용: [로빈 웨비나 전체](reference_robin_appintoss_webinar.md)

### 핵심 공식 1줄
```
뾰족한 세그먼트 → 클릭률 높음 → 토스가 더 뿌려줌 → DAU 폭발
넓은 세그먼트  → 클릭률 낮음 → 토스가 조용히 발송 중단 → 유저 0
```

### ⛔ 발송할 때 항상 제외 (어떤 앱이든)
```
고관여 투자자 (주식·파생상품 활발 거래자)
→ 소소한 포인트에 무반응 → 클릭률 죽임
```

### 점운 앱별 세그먼트 레시피

| 앱 | 포함 세그먼트 |
|---|---|
| 사주/꿈해몽 | 사주/운세 소비 이력 + 40~50대 여성 |
| 행운번호 | 복권/로또 소비 이력 |
| 궁합 | 데이팅 앱 소비 이력 + 20~30대 |
| 직운 | 이직 관련 소비 + IT/사무직 |
| MBTI | 자기계발 소비 + 심리테스트 관심 + 20~30대 |
| 다이어트 | 헬스/운동 소비 + 건강보조식품 구매 |
| 맘케어 | 자녀 보유 + 육아 관련 소비 |

### 발송 설정 3원칙
1. **AND 조건** (OR 최소화) — 더 뾰족하게
2. **50% 비율** (100% = 너무 넓음)
3. **AB 테스트 2개** 메시지 동시 발송 → 주 단위 비교

### 메시지 공식
```
[앱 핵심 기능] + [포인트 금액 명시]
예: "오늘 사주 확인하고 100포인트 받아가세요"
    "먹은 칼로리 체크하고 50포인트 받아가세요"
```

### 수익 목표
```
DAU 100 → 하루 1만원 수익 (광고 기반 현실적 첫 목표)
ECPM 5~7만원 = 뾰족한 타겟으로 데려온 유저의 결과
```

### 앱 설계 핵심 질문 (새 앱 만들 때마다)
