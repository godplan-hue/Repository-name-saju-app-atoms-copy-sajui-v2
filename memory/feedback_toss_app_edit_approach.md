# 토스 앱 수정 시 절대 규칙 (에러 방지)

**Why:** 2026-07-30 에스더님이 9개 앱 한꺼번에 수정하다 에러 → 새벽 4시간+21시간 총 삽질
**How to apply:** 토스 앱(.ait) 수정할 때마다 반드시 이 순서 지킬 것

## 수정 순서 (절대 바꾸지 말 것)

```
1개 앱 수정
    ↓
npx ait build 빌드 확인
    ↓
에러 없으면 → 다음 앱
에러 있으면 → 그 앱 먼저 수정 후 → 다음 앱
    ↓
반복 × 9
```

## 절대 금지

- ❌ 9개 앱 한꺼번에 수정 → 어디서 에러났는지 모름
- ❌ 빌드 확인 없이 다음 앱으로 넘어가기
- ❌ 첫 번째 앱 패턴 확정 전에 나머지 복붙하기

## 잠금 해제 코인 구현 원칙 (에러 방지)

### 동작 순서 (반드시 이 순서)
```
버튼 클릭
    ↓
coins >= 300 확인
    ↓ (부족하면 "광고 보고 700원 받기" 안내)
coins - 300 계산
    ↓
Toss Storage에 새 코인 저장 ("jeomun_coins")
    ↓
잠금 해제 상태 저장 ("unlocked_섹션명": "true")
    ↓
UI 업데이트 (잠금 버튼 → 콘텐츠 표시)
```

### Toss Storage 저장 키
- `jeomun_coins` — 현재 코인 잔액 (문자열로 저장)
- `unlocked_섹션명` — 잠금 해제된 항목 (예: `unlocked_detail`, `unlocked_advice`)
- `attendance_date` — 출석 날짜 (YYYYMMDD)
- `ad_date` — 광고 본 날짜
- `ad_count` — 오늘 광고 본 횟수 (최대 3)

### 코인 부족 시
- coins < 300 → "코인이 부족해요 🪙" + "광고 보고 700원 받기" 버튼 표시

### 절대 금지
- ❌ 코인 저장 전에 UI 먼저 업데이트 (저장 실패 시 코인만 사라짐)
- ❌ 잠금 해제 상태 저장 안 하기 (새로고침하면 다시 잠김)
- ❌ 코인 체크 없이 차감 (음수 코인 발생)

## 수정 방법 원칙 (항상 이렇게)
1. 한 가지 기능만 추가
2. 빌드 확인 (npx ait build)
3. 에러 없으면 다음 기능 추가
4. 절대 여러 기능 한꺼번에 추가 금지
